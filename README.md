
# Ref-System — Накопительная система лояльности «Гофермарт»

[![Go Version](https://img.shields.io/github/go-mod/go-version/sinfirst/Ref-System)](https://golang.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

**Ref-System** — это серверная часть накопительной системы лояльности для интернет-магазина «Гофермарт». Проект реализован в рамках дипломной работы курса «Go-разработчик» (Яндекс.Практикум).

Система позволяет пользователям регистрироваться, загружать номера заказов, получать за них баллы лояльности от внешнего сервиса-аккруала, а также тратить накопленные баллы на оплату следующих заказов.

## Функциональные возможности

*   **Регистрация и аутентификация пользователей** по паре логин/пароль.
*   **Загрузка номеров заказов** для расчёта баллов.
*   **Получение списка загруженных заказов** с информацией о статусе обработки и начисленных баллах.
*   **Просмотр текущего баланса** баллов лояльности и суммы уже списанных средств.
*   **Списание баллов** в счёт оплаты нового заказа.
*   **История списаний** с деталями по каждому выводу.
*   **Фоновая обработка заказов:** сервис периодически опрашивает внешнюю систему расчёта баллов (аккруал) и обновляет статусы заказов, начисляя баллы при успешной обработке.
*   **Защита от повторной загрузки:** номер заказа может быть привязан только к одному пользователю.

## Технологии

*   **Язык:** Go 1.21+
*   **Хранение данных:** PostgreSQL
*   **Маршрутизация и middleware:** стандартная библиотека `net/http` (либо используемый фреймворк)
*   **Конфигурация:** переменные окружения и флаги командной строки
*   **Валидация:** алгоритм Луна для проверки номеров заказов
*   **Аутентификация:** JWT (или другой механизм на ваше усмотрение)

## Установка и запуск

### Требования
*   Установленный Go (версия 1.21 или выше)
*   Установленный и запущенный PostgreSQL

### Инструкция

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/sinfirst/Ref-System.git
    cd Ref-System
    ```

2.  **Настройте базу данных:**
    *   Создайте базу данных в PostgreSQL.
    *   Примените миграции (если они есть в проекте). Обычно миграции находятся в директории `migrations` или описаны в `internal/storage`.
    *   *(Пример, если используется goose или migrate):* `goose postgres "postgres://username:password@localhost/dbname?sslmode=disable" up`

3.  **Запустите сервис:**
    ```bash
    go run cmd/gophermart/main.go
    ```
    Или соберите бинарный файл и запустите его:
    ```bash
    go build -o gophermart cmd/gophermart/main.go
    ./gophermart
    ```

## Конфигурация

Сервис конфигурируется через переменные окружения или флаги командной строки (приоритет у флагов).

| Параметр            | Переменная окружения   | Флаг      | Описание                                     | Пример значения                              |
|---------------------|------------------------|-----------|----------------------------------------------|----------------------------------------------|
| Адрес запуска сервера | `RUN_ADDRESS`          | `-a`      | Хост и порт, на котором запускается сервис | `localhost:8080`                             |
| Строка подключения к БД | `DATABASE_URI`       | `-d`      | DSN для подключения к PostgreSQL            | `postgres://user:pass@localhost/gophermart?sslmode=disable` |
| Адрес системы расчёта (аккруал) | `ACCRUAL_SYSTEM_ADDRESS` | `-r` | Базовый URL внешнего сервиса начислений     | `http://localhost:8081`                      |

Пример запуска с флагами:
```bash
./gophermart -a ":8080" -d "postgres://..." -r "http://accrual:8080"
```

## API

Система предоставляет REST-like HTTP API. Все запросы и ответы, где ожидается JSON, должны содержать заголовок `Content-Type: application/json`. Эндпоинты, требующие аутентификации, проверяют наличие и валидность JWT-токена (обычно в заголовке `Authorization: Bearer <token>`).

### 1. Регистрация пользователя
**`POST /api/user/register`**

Регистрирует нового пользователя. Логин должен быть уникальным. После успешной регистрации происходит автоматическая аутентификация (возвращается токен).

*Тело запроса:*
```json
{
    "login": "ivanov",
    "password": "secretpassword"
}
```

*Ответы:*
- `200 OK` – успешная регистрация и аутентификация.
- `400 Bad Request` – неверный формат запроса.
- `409 Conflict` – логин уже занят.
- `500 Internal Server Error` – внутренняя ошибка сервера.

### 2. Аутентификация пользователя
**`POST /api/user/login`**

Аутентифицирует пользователя по логину и паролю. При успехе возвращает токен.

*Тело запроса:*
```json
{
    "login": "ivanov",
    "password": "secretpassword"
}
```

*Ответы:*
- `200 OK` – успешная аутентификация.
- `400 Bad Request` – неверный формат запроса.
- `401 Unauthorized` – неверная пара логин/пароль.
- `500 Internal Server Error` – внутренняя ошибка сервера.

### 3. Загрузка номера заказа
**`POST /api/user/orders`** (требуется аутентификация)

Загружает номер заказа для расчёта баллов. Номер должен состоять из цифр и проходить проверку по алгоритму Луна.

*Тело запроса:* `text/plain` (номер заказа)
```
12345678903
```

*Ответы:*
- `200 OK` – номер заказа уже был загружен этим пользователем.
- `202 Accepted` – новый номер заказа принят в обработку.
- `400 Bad Request` – неверный формат запроса.
- `401 Unauthorized` – пользователь не аутентифицирован.
- `409 Conflict` – номер заказа уже был загружен другим пользователем.
- `422 Unprocessable Entity` – неверный формат номера заказа (не проходит алгоритм Луна или содержит нецифровые символы).
- `500 Internal Server Error` – внутренняя ошибка сервера.

### 4. Получение списка заказов
**`GET /api/user/orders`** (требуется аутентификация)

Возвращает список всех загруженных пользователем заказов, отсортированных по времени загрузки (от новых к старым).

*Ответы:*
- `200 OK` – успешная обработка, тело ответа содержит массив заказов.
  ```json
  [
      {
          "number": "9278923470",
          "status": "PROCESSED",
          "accrual": 500,
          "uploaded_at": "2020-12-10T15:15:45+03:00"
      },
      {
          "number": "12345678903",
          "status": "PROCESSING",
          "uploaded_at": "2020-12-10T15:12:01+03:00"
      },
      {
          "number": "346436439",
          "status": "INVALID",
          "uploaded_at": "2020-12-09T16:09:53+03:00"
      }
  ]
  ```
- `204 No Content` – у пользователя нет загруженных заказов.
- `401 Unauthorized` – пользователь не аутентифицирован.
- `500 Internal Server Error` – внутренняя ошибка сервера.

**Возможные статусы заказов:**
- `NEW` – заказ загружен, но ещё не отправлен в систему расчёта.
- `PROCESSING` – идёт расчёт вознаграждения.
- `INVALID` – система расчёта отказала в начислении (заказ недействителен).
- `PROCESSED` – расчёт успешно завершён, начислены баллы (поле `accrual` присутствует).

### 5. Получение текущего баланса
**`GET /api/user/balance`** (требуется аутентификация)

Возвращает текущий баланс баллов и общую сумму списанных баллов.

*Ответы:*
- `200 OK`
  ```json
  {
      "current": 500.5,
      "withdrawn": 42
  }
  ```
- `401 Unauthorized`
- `500 Internal Server Error`

### 6. Запрос на списание баллов
**`POST /api/user/balance/withdraw`** (требуется аутентификация)

Списывает указанное количество баллов в счёт оплаты нового заказа. Номер заказа (гипотетический) должен быть передан в теле запроса.

*Тело запроса:*
```json
{
    "order": "2377225624",
    "sum": 751
}
```

*Ответы:*
- `200 OK` – списание выполнено успешно.
- `401 Unauthorized` – пользователь не аутентифицирован.
- `402 Payment Required` – на счету недостаточно средств.
- `422 Unprocessable Entity` – неверный формат номера заказа.
- `500 Internal Server Error` – внутренняя ошибка сервера.

### 7. Получение информации о выводах средств
**`GET /api/user/withdrawals`** (требуется аутентификация)

Возвращает историю списаний баллов, отсортированную по времени (от новых к старым).

*Ответы:*
- `200 OK`
  ```json
  [
      {
          "order": "2377225624",
          "sum": 500,
          "processed_at": "2020-12-09T16:09:57+03:00"
      }
  ]
  ```
- `204 No Content` – списаний не было.
- `401 Unauthorized`
- `500 Internal Server Error`

## Взаимодействие с внешней системой расчёта (аккруал)

Для получения информации о начисленных баллах сервис обращается к внешнему API аккруала по адресу, указанному в конфигурации (`ACCRUAL_SYSTEM_ADDRESS`).

**Эндпоинт внешнего API:**
`GET /api/orders/{number}`

**Пример запроса от сервиса:**
```
GET /api/orders/12345678903 HTTP/1.1
```

**Пример успешного ответа (200 OK):**
```json
{
    "order": "12345678903",
    "status": "PROCESSED",
    "accrual": 500
}
```

**Возможные статусы от аккруала:**
- `REGISTERED` – заказ зарегистрирован, расчёт ещё не произведён.
- `INVALID` – заказ не принят к расчёту.
- `PROCESSING` – расчёт в процессе.
- `PROCESSED` – расчёт окончен, баллы начислены.

Сервис «Гофермарт» периодически (с учётом ограничений по частоте запросов) опрашивает аккруал для каждого заказа в статусе `NEW` или `PROCESSING` и обновляет статус заказа и начисленные баллы в своей базе данных.
